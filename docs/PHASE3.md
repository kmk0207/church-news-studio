# 주간 광고 제작 안내

## 실행과 저장

`run-studio.cmd` 또는 `python -m streamlit run app.py`로 실행하고 `http://127.0.0.1:8501`을 연다. 설치 방법은 README를 참고한다. 최초 실행 이후에는 API 키 없이 로컬 제작이 가능하다. 서버를 종료하면 화면도 종료되지만 저장한 프로젝트·사진·이미지는 `outputs/studio/`에 남는다. 이 폴더는 Git 제외 대상이다.

## 1. 고정 표지

새 작업에는 예배 표지 한 장이 자동으로 포함된다. 주간 화면에서 표지 틀을 선택하거나 필수 항목을 없애지 않는다. 다음 항목과 순서는 고정이다.

- 중앙 사진, 오른쪽 Song List, 날짜·시간, 환영 문구, 교회·예배실, YES! / Ethos Spirit.
- 인도자, 기도, 성경봉독, 설교자 항목 4개.

매주 입력하는 값은 날짜·시간·곡명·담당자/성경 본문·중앙 사진이다. 교회 이름·장소·환영 문구·브랜드·슬로건은 ‘표지 기본 설정’에서 최초 설정한다. 기존 확인된 로컬 표지가 있으면 그 고정정보를 초기 참고값으로 읽는다. 과거 담당자·성경 본문은 새 작업에 자동 복사하지 않는다.

고정정보를 변경하면 기존 표지는 다시 생성해야 한다. 날짜·순서·사진·곡명이 부족하면 송출본 생성이 거부된다. ‘초안으로 표시’를 선택하면 사진·곡명 대기 표시가 있는 초안을 확인할 수 있다. 초안은 전체 송출 ZIP에 포함하지 않는다.

## 2. 번호별 광고 입력

다음처럼 입력한다. [예제 파일](../examples/numbered-announcements.txt)을 복사해도 된다.

```text
0. 새신자 환영
1. 10월 생일축하
2. 추수감사 특새 광고 (복장, 모임시간)
3. 광고 이후 추수감사 특송 연습
4. 배트민턴 광고 (우천시 취소)
```

이 입력은 **고정 표지 1장 + 광고 5장 = 총 6장**이다. 0번도 일반 광고 번호이며 표지 번호가 아니다. 번호 뒤의 여러 줄이나 빈 줄은 같은 광고에 포함한다. 번호 중복·번호 없는 머리말은 거부하며 최대 30개를 지원한다.

같은 화면에서 목록을 다시 만들면 기존 번호 광고를 새 목록으로 교체한다. 표지와 별도로 추가한 수동 광고는 유지한다. 이전 저장본은 SQLite의 project_revisions에 남기지만 이전 버전 복원 UI는 아직 없다. ‘제작 기록 → 새 주로 복사’를 사용하면 지난주 프로젝트 자체도 별도로 보존된다.

## 3. 사진은 광고 번호에 연결

‘사진 보관함’에서 여러 사진을 등록하고 광고 입력 화면에서 ‘0번 사진’, ‘1번 사진’처럼 해당 번호에 연결한다. 사진이 없는 번호는 텍스트형, 있는 번호는 사진형이다. 광고 한 장당 사진 3개까지, 표지는 중앙 사진 1개를 사용한다.

사진 위치와 확대율은 광고 편집에서 선택적으로 조절한다. 사진 배정은 AI가 결정하거나 바꾸지 않는다. 표지 사진과 번호 0번 광고 사진은 서로 별개이다. 원본 사진은 수정하지 않고 로컬 보관함에 파일 내용 해시로 저장한다.

## 4. 문체 작성

‘번호별 광고 만들기 · 기본 말투’는 외부 전송·비용 없이 환영, 생일, 특새, 특송 연습, 배드민턴 등의 정형 메모를 교회 안내 문장으로 바꾼다. 예를 들어 특송 메모는 ‘광고 이후 추수감사 특송 연습이 있습니다~ 함께 참여해 주세요.’로 작성한다. 이는 제한된 로컬 규칙이며 모델 학습은 아니다. 지원하지 않는 자유로운 메모는 원문을 보존하므로 직접 수정하거나 AI 작성을 이용한다.

Gemini는 문체 지침과 Few-shot 예시로 자연스러운 제목·본문을 작성한다. 기존 structure 작업의 ‘원문 발췌’ 검사와 별도인 copy 작업을 사용하므로 새 문장을 허용한다. 번호·순서·페이지 수와 사진 연결은 코드가 고정한다. AI에게 사진 파일이나 배정 정보는 보내지 않는다.

모델 ID와 API 키를 입력하고 실제 전송할 원문을 확인한 뒤 동의해야 실행할 수 있다. API 키는 브라우저의 서버 세션에서만 사용하고 DB·파일에는 저장하지 않는다. 원문이 바뀌면 기존 전송 동의를 재사용하지 않는다. 이번 개발에서는 실제 API 호출 없이 모의 응답으로 연결을 검증했다. 실 API의 모델 호환·문장 품질·과금은 별도 검증이 필요하다.

문체 작성 후 숫자의 추가·누락, 명시한 일시/장소/복장 등의 값 변경, ‘우천시 취소’ 조건 누락을 검사한다. 검사는 인명이나 모든 자연어 조건의 진위를 증명하지 않는다. 원문과 작성 문장을 화면에서 비교하고 최종 검토해야 한다.

‘복장, 모임시간’만 입력한 경우 실제 값이 없으므로 복장이나 시간을 만들어 내지 않고 확인 요청을 표시한다. 필요한 값을 원문에 `복장: 흰색 상의`, `모임시간: 오전 5시`처럼 실제 정보로 추가한 뒤 다시 작성하거나 편집 화면에서 직접 보충한다.

## 5. 미리보기와 다운로드

광고별 문구를 검토하고 ‘변경 사항 저장’ 또는 ‘저장하고 미리보기 생성’을 누른다. 수정한 내용과 이전 이미지가 다르면 이전 이미지 다운로드를 차단한다. 표지를 포함해 출력할 광고의 내용을 모두 확인·저장하고 송출본으로 생성해야 전체 ZIP 다운로드가 활성화된다.

PNG/JPG 개별 다운로드, PNG/JPG 전체 ZIP, 1920×1080 또는 4K 출력을 지원한다. 글자가 너무 길면 임의로 생략하거나 두 페이지로 나누지 않고 생성을 중단하므로 해당 번호의 문구를 줄인다.

SQLite 제작 기록·다음 주 복사·같은 광고 이미지 재사용·동시 편집 충돌 감지를 지원한다. 다음 주 복사 시 표지 날짜와 검토 상태를 초기화한다. 바꾸지 않은 상세 광고는 내용을 확인한 뒤 기존 이미지를 유지할 수 있다.

## 현재 검증 범위

Streamlit AppTest 위젯 흐름, 번호별 사진 연결, SQLite 저장·복사·이전 저장본 보존, Gemini 모의 응답과 전송 동의 경계, 실제 Chromium PNG/JPG/ZIP 생성으로 검증한다. 컴퓨터 사용 도구의 브라우저 URL 판별 문제로 직접 브라우저 클릭·시각 QA는 완료하지 않았다. 실제 교회 사진·Song List와 실제 Gemini 응답 품질은 사용자 자료 및 동의 후 추가 검증이 필요하다. PPTX·서버 배포는 포함하지 않는다.
